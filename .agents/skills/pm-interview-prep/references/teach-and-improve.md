# Teach and Improve

## Teaching an answer (Learn mode) - "I do, we do, you do"
1. **What it tests** (1-2 lines) and which interviewers love/hate.
2. **Framework** from `frameworks.md` (and `ai-pm.md` for AI).
3. **Model answer outline** (bullets, not a script) with narration of *why* each move is made, including what a weak answer does instead.
4. **Guided practice ("we do"):** give a fresh question; ask the candidate for the first step only (clarifying questions); give feedback; go to next step.
5. **Solo ("you do"):** a new question, full answer, then score.
6. **Recap:** 5-line cheat card for the category.

## Improve loop (after scoring)
1. Name the single highest-leverage gap (not everything).
2. Show **before -> after** for that segment, built from the candidate's own words:
   - *Before:* quote
   - *After:* tighter/stronger version (outline)
   - *Why it's better:* tie to the rubric dimension
3. Give a **targeted drill** (see below), 5-10 minutes.
4. **Re-ask a variant** of the question; compare scores; show the delta.
5. Move on after two attempts or a score of >= 4 in that dimension.

## Fix library
| Gap | Fix | Drill |
|---|---|---|
| Rambling | Open with a 3-bullet roadmap; one sentence per step summary | Answer in 90 seconds, then expand |
| Jumps to solutions | Force 3 clarifying questions + goal restatement | "Clarify only" drill on 5 prompts |
| Generic users | Segment by need/behaviour, pick one with criteria | Write 3 segments and justify choice in 60 s |
| Weak ideas | Brainstorm by lens: pain point, moment, modality, constraint-flip | 10 ideas in 3 minutes, then cluster |
| No prioritisation | Explicit criteria (impact, effort, risk) and say "I'd start with..." | Rank 6 ideas with RICE aloud |
| Metrics soup | Goal -> one North Star -> 2-3 inputs -> guardrail | Define metrics for 5 products in 5 minutes |
| No root-cause method | Data check -> external -> internal -> segment -> hypotheses | Run the checklist on 3 "metric dropped" prompts |
| No recommendation | End with "I recommend X because A, B; risks C; first test D" | Write a 3-sentence closing for 5 old answers |
| Estimation sloppy | Label assumptions, round, cross-check | 5 Fermi problems with 2-method cross-check |
| Technical shallow | Requirements -> components -> one flow -> trade-offs | Draw the architecture of 3 products you use |
| AI hand-waving | Baseline, eval, failure modes, cost | For any AI idea, answer "How is it evaluated and what does a request cost?" |
| Too long | Time boxes; drop the least important section | Re-do in 70% time |

## Teaching style rules
- Lead with the principle, then the example; keep examples short.
- Ask the candidate to explain the framework back in their own words.
- Praise specific behaviours ("you stated an assumption before computing") not generically.
- Never give the whole answer when a hint will do; escalate hint -> outline -> example.
- Adapt to level: APM gets structure and empathy; Senior gets strategic framing, ambiguity handling, influence.

## Pattern bank of strong moves
- "Before I jump in, let me confirm the goal and constraints."
- "I see three user groups; I'll focus on X because..."
- "My criteria for choosing are impact, effort and risk."
- "The biggest assumption is...; I'd validate it by..."
- "If I had to ship in four weeks, I'd..."
- "To summarise: recommendation, why, risks, next step."

## Rewrite format for a full answer (on request only)
Produce an *outline-level* improved answer under the same time box, explicitly marked as an example for study, not a script. Highlight where each rubric dimension improved.
