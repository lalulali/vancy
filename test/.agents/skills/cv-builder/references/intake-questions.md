# Intake Questions (CV)

Ask in rounds of 3–5 questions; never dump the whole list. Skip only basic administrative facts (name, dates, titles) already answered by an uploaded CV or LinkedIn export — **never skip deep-dive questions on responsibilities, technical details, methods, personal ownership, and achievements.** An existing CV is a compressed summary that almost always omits technical depth, system scale, architecture decisions, and metrics that a target job ad cares about. Always interview the user to uncover those details before writing or retargeting. Accept rough notes; the skill does the writing once the facts are confirmed.

## Round 1 — Target (always first)
1. What role(s) are you targeting? Paste the job ad if you have one.
2. Which country/market is the employer in? (sets length, page size, spelling, personal-data rules)
3. Current career stage: student/graduate, early (<5 yrs), mid (5–10), senior (10+), executive, career changer, returner?
4. Do you have an existing CV, LinkedIn profile, or notes I can start from?

## Round 2 — Identity & header
5. Name as it should appear; professional email; phone with country code; city & country; LinkedIn/portfolio/GitHub URL.
6. Work authorisation for the target country (only if applying cross-border).
7. Professional credentials with post-nominals you are entitled to use (e.g., CPA, PMP, PE).

## Round 3 — Each role & Technical / Retargeting Deep-Dive (repeat, most recent first; go deep on the last 10–15 years)
8. Title, employer, city/country, start–end month/year. Any promotions within the employer?
9. One sentence on the employer if not well known (industry, size, market).
10. Scope: team size you led or worked in, budget/revenue/portfolio, geography, number of clients/users/sites, who you reported to.
11. Core responsibilities (3–6) and exact personal ownership (what did you personally design, build, or decide versus the rest of the team?).
12. **Technical & domain depth (especially when matching a job ad):**
    - *Unlisted experience:* "The job ad asks for [Tool / Language / Framework / Architecture / Method X], which isn't on your current CV. Did you use X (or an equivalent) in this role?"
    - *Architecture & implementation ("the How"):* "For [System / Feature / Project Y], what was the exact tech stack, system architecture, data/traffic scale (e.g. RPS, dataset size, active users, microservices), and the hardest technical problem or trade-off you solved?"
    - *Engineering / technical metrics:* "Did your work improve latency (p95/p99), uptime/SLA, deployment frequency, incident rate, cloud/infra cost, query speed, test coverage, or developer velocity? By how much (before → after)?"
13. Achievements — for each: what changed, by how much (number, %, before→after, time), over what period, and **the exact method/technical approach you used** ("by doing Z"). Use the prompts below.

### Achievement prompts (ask 2–4 relevant ones per role)
- Made money: revenue, new clients, deals closed, upsell, pricing, market entry?
- Saved money: costs cut, cloud/infra savings, vendors renegotiated, waste reduced?
- Saved time: cycle time, build/deploy time, turnaround, automation, hours saved per week?
- Improved quality / reliability: errors, defects, p95 latency, uptime/SLA, compliance findings, satisfaction/NPS, ratings?
- Scaled: users, RPS/traffic volume, dataset size, headcount hired, sites opened, markets launched?
- Led: projects (budget, team, duration), architecture migrations, change programmes, firsts ("first in company to…")?
- Recognised: awards, rankings ("top 5 of 120"), promotions ahead of schedule, invitations to speak?
- Solved: a critical problem, bottleneck, crisis, audit, outage — how did you diagnose and fix it, and what was the outcome?

If the user has no numbers: ask for estimates they could defend in an interview ("roughly", "~"), ranges, scale words, or before/after descriptions. If figures are confidential: use percentages, ratios, or magnitude ("multi-million"). **Never invent or assume a number, tool, or technical method.** Mark any remaining unknowns as `[metric?]` or `[fact?]` in the draft and ask.

## Round 4 — Education, skills, extras
14. Degrees (degree, field, institution, country, year); honours/awards worth showing; for students: GPA (if strong), relevant modules, thesis/projects, expected graduation.
15. Certifications/licences (name, issuer, year, in-progress with expected date).
16. Hard skills, programming languages, frameworks, cloud/data tools, architectures, methodologies, and spoken languages (with proficiency).
17. Optional: publications, open-source contributions, patents, volunteering, extracurricular leadership, notable interests.
18. Gaps or unusual moves you want framed (career break, layoff, freelance, relocation).

## Round 5 — Output preferences
19. Template preference (offer `--list-templates` options with a recommendation), page size if not implied by market, spelling preference.
